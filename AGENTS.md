# Firebase work

Always look for and use the appropriate Firebase agent skills in `.agents/skills`
when performing tasks related to Firebase.

Use the existing Firebase project `heat-is-on-react` for this app.
Use Firebase Hosting for this Vite SPA, build with `npm run build`, and deploy
the `dist` directory with a fallback to `/index.html` for client-side routes.

# Project operations guide

Run all commands from the project root. This React / Vite SPA uses Firebase
Authentication (email and password), Cloud Firestore, and Firebase Hosting.

## Deployment targets and configuration files

- Firebase project: `heat-is-on-react`. Reuse its registered Web App.
- Firestore: Standard edition, `(default)` database, region `asia-southeast1`.
- Live site: https://heat-is-on-react.web.app
- Console: https://console.firebase.google.com/project/heat-is-on-react/overview
- `.firebaserc`: default Firebase project.
- `firebase.json`: Hosting, Auth, Firestore, and emulator configuration.
- `firestore.rules` and `firestore.indexes.json`: database rules and indexes.
- `src/firebase/config.js`: reads environment variables; do not hardcode configuration values.
- `public/presentation.json` and `public/media/`: introduction videos, hazard animations, and icons.

The current development branch is `starryoosky-dev`. Before making changes, run
`git status` and `git branch --show-current` to check the branch and working tree.
Preserve existing work.

## Configuration purposes, formats, and Git tracking

| File or directory | Purpose | Git tracking policy |
| --- | --- | --- |
| `.env.local` | Firebase Web App configuration for local development and builds | Do not commit the actual file; keep variable names and placeholders in the Initial setup section below |
| `.firebase/` | Local deployment cache generated by Firebase CLI | Do not commit the directory or its contents; retain structure and format examples in this guide |
| `firebase.json` | Shared deployment, database, and emulator configuration | Commit it so the team uses consistent deployment settings |
| `.firebaserc` | Project aliases and default project selection | Commit it; the current default is `heat-is-on-react` |

Keeping the formats means documenting examples in `AGENTS.md`. Do not commit an
empty `.env.local` or `.firebase/`, and do not recreate `.env.example`. Create
`.env.local` manually in new environments; Firebase CLI generates `.firebase/`.

### `.env.local`

Use dotenv format: one `VARIABLE_NAME=value` entry per line. The complete variable
list is in the next section. The app reads `import.meta.env.VITE_FIREBASE_*`, and
scripts read configuration through Vite `loadEnv`. The file is excluded from Git;
the built frontend still includes the Firebase Web configuration it needs to run.

### `.firebase/`

This directory contains deployment caches, not application connection settings or
production database backups. The current Hosting cache structure looks like:

```text
.firebase/
└── hosting.ZGlzdA.cache
```

The current CLI cache records one resource per line. Placeholder format:

```text
index.html,<file-timestamp-in-milliseconds>,<content-hash>
assets/index-<build-id>.js,<file-timestamp-in-milliseconds>,<content-hash>
```

The internal format may change between CLI versions. Do not write or maintain
cache files manually. The directory can be deleted and regenerated during the
next deployment. Do not add a `.gitkeep` file.

### `firebase.json`

This file contains no API key. The project's shared configuration has this format:

```json
{
  "auth": { "providers": { "emailPassword": true } },
  "firestore": {
    "database": "(default)",
    "location": "asia-southeast1",
    "rules": "firestore.rules",
    "indexes": "firestore.indexes.json"
  },
  "hosting": {
    "public": "dist",
    "ignore": ["firebase.json", "**/.*", "**/node_modules/**"],
    "rewrites": [{ "source": "**", "destination": "/index.html" }],
    "predeploy": ["npm run build"]
  },
  "emulators": {
    "auth": { "port": 9099 },
    "firestore": { "port": 8080 },
    "ui": { "enabled": false }
  }
}
```

`hosting.public` selects the upload directory, `predeploy` runs the build before
deployment, and `rewrites` enables direct navigation to SPA routes. `firestore`
points to the rules and indexes. Emulator ports must match the connection settings
in `.env.local`. Changing `location` does not migrate an existing database.

### `.firebaserc`

The default project is stored as JSON:

```json
{
  "projects": {
    "default": "heat-is-on-react"
  }
}
```

This file contains no API key. Deployment commands still explicitly pass
`--project heat-is-on-react` to make the target clear.

### Checks before committing

`.gitignore` excludes `.env.local` and `.firebase/`. Exception rules allow tracking
`firebase.json`, `.firebaserc`, `firestore.rules`, and `firestore.indexes.json`.
Do not use `git add -f` to stage local environment configuration or deployment caches.

```bash
git check-ignore .env.local .firebase/
git ls-files -- .env.local .firebase/
git status --short -- firebase.json .firebaserc
```

The first command should list both ignored paths. The second should return no
output, indicating that neither local configuration nor caches are tracked.
If it lists files, remove them from Git tracking while preserving local copies.
Adding ignore rules alone does not stop tracking files already in Git.

## Initial setup and environment variables

Install dependencies and check Firebase CLI:

```bash
npm ci
npx -y firebase-tools@latest --version
```

Firebase emulators also require a Java JDK supported by the current Firebase CLI.

Create `.env.local` in the project root and fill in these variables. The file is
ignored by Git, and this repository does not provide `.env.example`. New team
members should obtain configuration from the existing Web App.

```dotenv
VITE_FIREBASE_API_KEY=<apiKey>
VITE_FIREBASE_AUTH_DOMAIN=<authDomain>
VITE_FIREBASE_PROJECT_ID=heat-is-on-react
VITE_FIREBASE_STORAGE_BUCKET=<storageBucket>
VITE_FIREBASE_MESSAGING_SENDER_ID=<messagingSenderId>
VITE_FIREBASE_APP_ID=<appId>
VITE_FIREBASE_MEASUREMENT_ID=<measurementId>
VITE_USE_FIREBASE_EMULATORS=false
VITE_FIREBASE_AUTH_EMULATOR_URL=http://127.0.0.1:9099
VITE_FIREBASE_FIRESTORE_EMULATOR_HOST=127.0.0.1
VITE_FIREBASE_FIRESTORE_EMULATOR_PORT=8080
```

`measurementId` can be left empty. Emulator connection variables are used only in
development mode with `VITE_USE_FIREBASE_EMULATORS=true`. Restart the development
server after changing environment variables. Production configuration changes
require rebuilding and redeploying.

Retrieve configuration from Firebase Console > Project settings > General >
the existing Web App > SDK configuration. Alternatively, after CLI login, use
these commands, replacing `<APP_ID>` with the listed Web App ID:

```bash
npx -y firebase-tools@latest apps:list --project heat-is-on-react
npx -y firebase-tools@latest apps:sdkconfig WEB '<APP_ID>' --project heat-is-on-react
```

Do not copy actual configuration values into `AGENTS.md` or source code. CI/CD must
provide the same environment variables to the build job before `npm run build`.

## Firebase login and existing resource checks

```bash
npx -y firebase-tools@latest login
npx -y firebase-tools@latest projects:list
npx -y firebase-tools@latest use heat-is-on-react
npx -y firebase-tools@latest firestore:databases:list --project heat-is-on-react
npx -y firebase-tools@latest firestore:databases:get '(default)' --project heat-is-on-react
```

Use `login --no-localhost` when a local callback is unavailable. CLI credentials
are used for deployment; application accounts are used to play the game. New team
members need the appropriate permissions on the Firebase project.

The project is already initialized. Do not rerun `firebase init`, create another
project, register a duplicate Web App, or create another database. The email/password
Authentication provider should be enabled. Check or restore it in Firebase Console >
Authentication > Sign-in method. Its configuration is also recorded in `firebase.json`.

## Local development and validation

To run against the live Firebase project, disable emulators in `.env.local` and run:

```bash
npm run dev
```

Vite defaults to port `5173` but may choose another port if it is occupied. Use the
URL printed in the terminal.

For local emulators, start Auth and Firestore in the first terminal:

```bash
npx -y firebase-tools@latest emulators:start --only auth,firestore --project demo-heat-is-on-react
```

Start the development server against those emulators in a second terminal:

```bash
VITE_USE_FIREBASE_EMULATORS=true VITE_FIREBASE_PROJECT_ID=demo-heat-is-on-react npm run dev
```

Add `--import <data-directory> --export-on-exit <data-directory>` to the emulator
startup command to restore and save local data. Without an export directory, do
not assume data survives a restart.

Standard validation commands:

```bash
npm run test:game
npm run test:i18n
npm run lint
npm run build
```

Changes to game transactions, database rules, or Firebase integration also require
emulator integration tests. Stop older emulators occupying ports `8080` and `9099`,
then run:

```bash
npx -y firebase-tools@latest emulators:exec --only auth,firestore --project demo-heat-is-on-react 'npm run test:game:emulator'
```

This test requires both Auth and Firestore emulators and must not run against the
production database. `PERMISSION_DENIED` logs from rejected invalid writes may be
expected assertions; use the final PASS results and exit code to assess success.
Investigate other failures. A successful build alone does not verify functionality.

## Demo data

The script reads Firebase configuration from `.env.local`, creates missing demo
accounts and records, and preserves existing games. By default it writes to the
live project. Run it when needed, not as part of every deployment:

```bash
npm run seed:demo
```

To write only to running local emulators:

```bash
FIRESTORE_EMULATOR_HOST=127.0.0.1:8080 FIREBASE_AUTH_EMULATOR_HOST=127.0.0.1:9099 GCLOUD_PROJECT=demo-heat-is-on-react npm run seed:demo
```

## Production deployment

Before deploying, verify test results, the Firebase project, and build environment
variables. Hosting's `predeploy` automatically runs `npm run build`, then uploads
`dist`. There is no need to copy files manually.

For frontend, text, styling, or static media changes only:

```bash
npx -y firebase-tools@latest deploy --only hosting --project heat-is-on-react
```

When database rules change, deploy them before publishing frontend changes that
depend on them:

```bash
npx -y firebase-tools@latest deploy --only firestore:rules --project heat-is-on-react
npx -y firebase-tools@latest deploy --only hosting --project heat-is-on-react
```

When indexes change, deploy them first and confirm in the console that index
building has finished before publishing features that depend on them:

```bash
npx -y firebase-tools@latest deploy --only firestore:indexes --project heat-is-on-react
```

To deploy Hosting, rules, and indexes together:

```bash
npx -y firebase-tools@latest deploy --only hosting,firestore:rules,firestore:indexes --project heat-is-on-react
```

This combined command does not guarantee indexes finish building before the
frontend is published. Use separate steps for features requiring new indexes.
Hosting deployment does not update database records, run database migrations,
or publish rules that exist only locally.

## Release verification, previews, and rollback

Confirm that the CLI reports `Deploy complete!`. Open and refresh the live site,
then check:

1. Direct navigation and refresh work for `/login` and `/game/<actual-game-id>`.
2. Login, the game list, and English/Chinese language switching work.
3. New games support round selection and have the hazard wheel enabled by default.
4. Review is blocked until the current round's hazard is confirmed; canceling hazard confirmation still triggers the reminder.
5. Hazard animations and impact dialogs show all six towns, including Bludgeton.
6. Dividends, round advancement, early termination, and the closing summary work, and persisted database results can be loaded again.

Use a separate verification game to avoid changing games in active use. If the
site appears outdated, compare the build files referenced by the live page with
local `dist/index.html`, then check browser caching.

To preview the frontend without updating the live Hosting site:

```bash
npx -y firebase-tools@latest hosting:channel:deploy review --expires 7d --project heat-is-on-react
```

Preview sites still connect to the Firebase backend specified in the build
configuration. They do not provide a separate test database.

To roll back Hosting, open Firebase Console > Hosting > Release history and select
a previous release to roll back to. Restore the corresponding source versions of
database rules and indexes, then deploy them separately. Hosting rollback does not
restore rules, indexes, or database records. Record the branch, commit (if committed),
deployment scope, and verification results for each release.
